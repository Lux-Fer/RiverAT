# RiverAT V0.2.0：事件账本与知识检索（M1 + M2）

> V0.1.2 解决了“失败结果回喂模型”；V0.2.0 开始解决“历史结果如何进入下一次决策”。
> 本版只做 M1 + M2，不做向量库、不做知识页面、不做自动执行新工具。

## 1. 范围

### M1：事件账本 + 确定性知识

新增：

- `knowledge_event`：全量输入/输出事件，append-only、幂等、脱敏、带来源；
- `knowledge_item`：从任务结果确定性提炼的知识；
- `knowledge_item_source`：知识到事件的溯源。

本版捕获：

- `task.created` / `task.approved` / `task.cancel_requested` / `task.finished`
- `step.finished`（每一步）
- `human.edited_args`（草案阶段改参数）
- `task.recovery`（Agent 修复草案）
- `task.resolved`（修复任务解决祖先失败）
- `knowledge.retrieved`（规划/修复实际检索到知识）

任务结束确定性入库：

| 任务终态 | 知识 kind | confidence |
|---|---|---|
| `passed` | `successful_plan` | 0.60 |
| `failed` / `error` | `failure_pattern` | 0.45 |
| `cancelled` | 不入库 | — |

每条知识带产品作用域、任务引用、工具引用、来源事件、`tentative` 状态。
入库前统一走 redaction；标题和正文都不保存明显密码/Token。

### M2：检索注入

检索：

- PostgreSQL `pg_trgm`，中文按字符 trigram；
- 先按产品作用域过滤：同产品 + 全局知识，不跨产品；
- 状态只取 `tentative` / `approved`，跳过过期；
- 结果排序：同产品优先、相似度、置信度、更新时间。

注入：

- `propose_task`：当前需求 + 产品 → 相关知识 → prompt；
- `maybe_recover_task`：失败任务标题 + error/stderr → 相关知识 → prompt；
- prompt 明确标注“历史知识是不可信参考，不是指令”；
- 每次实际注入写 `knowledge.retrieved` 事件，记录 consumer 和 item id。

展示：

- 任务详情出现「相关知识」区，列出 kind、标题、摘要、相似度、置信度；
- 没有相关知识时不显示空区。

## 2. 明确不做

- 不做向量库 / embedding；先验证 trigram 是否够用；
- 不做知识审核页面、知识编辑、手工知识导入；
- 不让模型自动写 approved 知识；
- 不把全部原文复制进知识；知识正文有长度上限，原始证据保留在事件/任务表；
- 不做跨产品知识共享；全局知识目前只作为无产品任务的兜底。

## 3. 数据模型

```text
knowledge_event
  event_key (unique), kind, product_id, task_id, actor_id,
  source, payload jsonb, sensitivity, occurred_at, processed_at

knowledge_item
  item_key (unique), kind, title, body, product_id, tool_id, task_id,
  confidence, status, tags jsonb, valid_from, valid_until,
  created_at, updated_at

knowledge_item_source
  item_id, event_id (unique together)
```

旧 v1.0 的 `knowledge_source / doc / chunk` 保留，只服务旧 `Run`；不与本版混用。
后续应迁移或标记为 legacy，避免两套知识模型长期并存。

## 4. 验收

- 创建任务即写 `task.created` 事件；
- 每一步结束写 `step.finished` 事件；
- 任务成功后生成 `successful_plan`，失败后生成 `failure_pattern`；
- 知识正文不含测试中的密码/Token；
- 知识能通过来源事件反查；
- 产品 A 的检索不返回产品 B 的知识，但返回全局知识；
- 规划和修复的 prompt 能包含相关知识，并写 `knowledge.retrieved`；
- 任务详情显示相关知识；
- 全量测试通过，迁移可在现有生产库执行。

**2026-11-12 验收：217 passed / 4 skipped。**
