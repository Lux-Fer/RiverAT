# RiverAT V0.2.1：记忆作用域、有效期与人工反馈（M3 第一切片）

> V0.2.0 让历史任务进入检索；V0.2.1 回答三个问题：
> 这条知识属于谁、什么时候过期、人觉得它有没有用。

## 1. 作用域

`knowledge_item` 新增：

- `scope`：`global` / `product` / `user`
- `owner_id`：用户作用域时指向用户

自动入库规则：

| 任务 | scope | owner |
|---|---|---|
| 有产品 | `product` | 空 |
| 无产品、有创建者 | `user` | 任务创建者 |
| 无产品、无创建者 | `global` | 空 |

检索只返回：

- 所有 `global`；
- 当前产品的 `product`；
- 当前用户的 `user`。

产品 A 不会返回产品 B 的知识；用户 A 不会返回用户 B 的私有知识。

`team` 作用域暂缓：当前没有团队实体，硬造一个字符串会把权限做坏；等有团队模型再加。

## 2. 有效期（TTL）

自动知识带 `valid_until`：

- 失败模式：默认 30 天；
- 成功方案：默认 90 天；
- 可通过 `KNOWLEDGE_FAILURE_TTL_DAYS` / `KNOWLEDGE_SUCCESS_TTL_DAYS` 调整。

检索会跳过 `valid_until <= now()` 的知识。本版不做后台删除和按时间自动降置信度；
先用有效期控制“旧经验不要无限期生效”。

## 3. 人工反馈

任务详情的「相关知识」每条增加：

- **有用**：置信度 +0.10，状态改为 `approved`；
- **不相关**：置信度 -0.05，低于 0.20 时归档。

同一用户、同一条知识、同一次任务只保留一条反馈；再次提交是更新。
反馈同时写：

- `knowledge_feedback` 表；
- `knowledge.feedback` 事件；
- 审计日志 `knowledge.feedback`。

这让“人觉得这条知识对不对”成为可追溯信号，而不是只靠模型自评。

## 4. 验收

- 产品 A 检索不到产品 B 的知识；
- 用户 A 检索不到用户 B 的私有知识；
- 过期知识不出现在检索和任务详情；
- 有用反馈提升置信度并变为 approved；
- 不相关反馈降低置信度；
- 反馈产生表记录、事件和审计；
- 全量测试通过。

**2026-11-12 验收：219 passed / 4 skipped。**

## 5. 本版不做

- 团队作用域（缺团队实体）；
- 自动时间衰减曲线；
- 后台 TTL 清理任务；
- 知识审核/编辑页面；
- 从“拒绝理由”自动生成新知识；
- 向量检索与离线评测。

这些放到 M4 或后续记忆版本。
