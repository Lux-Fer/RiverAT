# RiverAT V0.2.3：混合排序、检索指标与评测骨架（M4 第一切片）

> 本版不做 pgvector。先把“排序是否更好、检索是否命中、知识是否被使用”
> 做成可观察、可回归的东西；语义向量留到有真实 embedding 条件时。

## 1. 混合排序

检索仍以 PostgreSQL `pg_trgm` 为召回，但排序从单一相似度改为：

```text
score =
  0.65 × similarity(title + body, query)
+ 0.25 × similarity(title, query)
+ 0.05 × confidence
+ 0.05 × 反馈有用率（无反馈时取 0.5）
```

同时保留：

- 作用域优先：同产品 → 用户 → 全局；
- 过期过滤；
- 当前任务自己的知识排除；
- 产品/用户隔离。

这是 **结构化 + 词法** 的混合排序，不是语义向量检索。

## 2. 检索指标

控制台显示最近 30 天：

- 检索次数；
- 无命中次数和比例；
- 平均召回条数；
- 反馈总数与“有用”比例。

数据来自 `knowledge.retrieved` 事件。现在**空结果也写事件**，所以能计算
no-result rate；此前只有命中才写，指标会失真。

## 3. 评测骨架

新增 `app/evaluation/knowledge_eval.py`：

```python
RetrievalCase(query, expected_item_key, product_id, user_id, expect_empty)
evaluate_retrieval(session, cases) -> RetrievalReport
```

输出：

- `hit_at_1`
- `hit_at_3`
- `mrr`
- 每个 case 的 rank 和实际返回 item_key

测试覆盖：

- 正确知识命中；
- 过期知识不返回；
- 产品 A 不返回产品 B；
- 预期空结果。

后续把真实任务样本加入 `RetrievalCase` 列表，就能做回归评测；不需要先上向量库。

## 4. 验收

- 控制台显示检索指标；
- 空检索也写 `knowledge.retrieved` 事件；
- 混合排序能召回；
- 评测骨架在固定 case 上给出 hit@1 / hit@3 / MRR；
- 产品隔离、过期过滤仍有效；
- 全量测试通过。

**2026-11-12 验收：226 passed / 4 skipped。**

## 5. 本版不做

- pgvector / embedding；
- 真实模型回答质量评测；
- 知识污染自动检测；
- 定时评测任务；
- 前端评测页面（目前是 service + pytest + 控制台指标）。
