# RiverAT V0.3.0：步骤级判断与单步修复

> V0.2.x 让模型在任务结束后观察失败；V0.3.0 让它在**每一步之后**参与控制流，
> 并在单步失败时提出**同任务**的修复草案。
> 但权限边界不变：模型不能自动执行新工具，所有替换步骤仍需人确认。

## 1. 执行监督器

每步成功且仍有剩余步骤时：

```text
step result → 执行监督 LLM → continue / stop
```

- `continue`：执行下一条已经批准的计划；
- `stop`：把剩余 pending 步骤标为 skipped，任务按已完成聚合；
- 不修改计划、不调用工具、不新建步骤；
- 模型不可用/返回非法 JSON/超预算：默认 `continue`，不阻塞任务。

停止原因写入：

- `task.draft.step_decisions`；
- `agent.step_decision` 事件；
- 任务详情「Agent 执行判断」。

## 2. 单步失败修复

某一步失败后，修复规划器最多提出 **一个替换工具调用**：

```text
failed step → 修复 LLM → 一个 tool_call → 校验 → task.paused
                                                        ↓
                                              人确认后 resume
                                                        ↓
                                     同任务替换该步骤并继续执行
```

- 任务进入 `paused`，不创建新的 draft 任务；
- 失败步骤保留原状态，修复参数存在 `task.draft.repair`；
- 人工确认后，替换失败步骤的工具/参数，步骤重置为 pending；
- 已经 passed 的步骤不重跑；后续 pending 步骤继续；
- 修复次数上限默认 2；
- 失败步骤的替换仍走 schema 校验和审计。

## 3. 断点续跑

`error` 任务可手动“断点续跑”：

- 保留 `passed` / `skipped` 步骤；
- 把 `running` / `failed` / `error` 步骤重置为 `pending`；
- 记录旧状态到 `task.draft.resume_attempts`；
- 任务重新入队，已通过步骤不重跑。

这不是自动恢复；worker 崩溃后仍由人决定是否从断点继续。

## 4. 预算与配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `AGENT_STEP_REVIEW_ENABLED` | `true` | 是否在每步成功后调用监督模型 |
| `AGENT_STEP_REVIEW_LIMIT` | `4` | 单任务最多监督次数，控制成本 |
| `AGENT_STEP_REPAIR_ENABLED` | `true` | 单步失败后是否提出同任务修复 |
| `AGENT_STEP_REPAIR_LIMIT` | `2` | 单任务最多修复次数 |

`stop` 只跳过尚未执行的已批准步骤；修复必须人确认，不产生自动副作用。

## 5. 安全边界

- 监督器只处理 `passed` 的步骤，只能 continue/stop；
- 修复器只提出一个替换步骤，不能新增多步计划；
- 修复会暂停任务，等人确认后才执行；
- 仍受任务终态、队列、审计、知识事件约束；
- LLM 调用异常不改变任务结果。

## 6. 验收

- 两步任务，第一步成功后模型 `stop`：第二步 skipped，任务 passed；
- 决策写入 `step_decisions`、事件和任务详情；
- 单步失败后模型提出替换：任务 paused，不创建新任务；
- 确认修复后同任务继续，passed 步骤不重跑；
- error 任务断点续跑：passed 保留，running/failed 重置后继续；
- 修复失败超过上限后回到失败/恢复策略；
- 模型不可用时继续执行；
- 全量测试通过。

**2026-11-12 验收：229 passed / 4 skipped。**

## 7. 与“完整 Agent”的距离

V0.3.0 补上了：

- 每步观察 → continue/stop；
- 单步失败 → 同任务 repair 草案 → 人确认 → resume；
- error 任务保留已通过步骤，从断点续跑。

仍缺少：

- 无人工确认的自动重试/重规划；
- 无人值守的崩溃自动恢复（当前仍需人点续跑）；
- 风险分级授权；
- 工具沙箱与远程 runner；
- 修复轨迹的完整回放与对比评估。
