# RiverAT V0.3.1：只读工具的风险分级授权

> 之前所有任务都要人确认。V0.3.1 只放开一种最低风险：**全部步骤都是显式
> `read_only` 工具**时，平台自动确认并执行；写入/高风险仍必须人确认。

## 1. 工具风险

`tool.json` 新增可选字段：

```json
{"risk": "read_only"}
```

取值：

| 值 | 含义 | 默认策略 |
|---|---|---|
| `read_only` | 只读检查，不改变被测系统 | 可自动确认（需全部步骤） |
| `write` | 有副作用 | 人工确认 |
| `dangerous` | 高风险副作用 | 人工确认（后续可加双人复核） |

不写默认 `write`，保守处理。工具上传时校验非法 risk 值。

## 2. 自动确认条件

必须同时满足：

- `AGENT_AUTO_APPROVE_READ_ONLY=true`（默认 true）；
- 任务处于 draft；
- 有至少一个步骤；
- **每个步骤**的工具都是 approved 且 `risk=read_only`。

满足后：

- 任务直接变为 `queued`；
- `approved_by` 为空，`approved_at` 记录时间；
- `task.draft.auto_approved=true`；
- 写 `task.auto_approve` 审计和 `task.auto_approved` 事件；
- assistant / 手动任务的创建入口自动派发。

任一步骤是 write/dangerous、工具停用或缺失，任务保持 draft 等人确认。

## 3. 显示

- 工具页显示「只读 / 写入 / 高风险」；
- 自动确认任务详情显示「已按只读工具策略自动确认；没有人工放行」；
- 任务 board 按 queued 正常显示。

## 4. 安全边界

- 自动确认只基于**工具作者显式声明**的 risk；admin 审核工具时仍要判断声明是否可信；
- 平台不会根据名字/输出猜测风险；
- 自动确认不会绕过执行超时、审计、事件、工具停用校验；
- 单步修复和断点续跑仍需要人确认。

## 5. 验收

- 全部 read_only 的草案自动 queued；
- 任一步骤 write 的草案保持 draft；
- 自动确认写审计和事件；
- 工具页显示 risk；
- 全量测试通过。

**2026-11-12 验收：231 passed / 4 skipped。**

## 6. 本版不做

- dangerous 的双人复核；
- 按步骤混合风险的自动放行；
- 运行时沙箱/网络白名单；
- 从工具输出自动推断风险等级。
